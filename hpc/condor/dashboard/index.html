Running jobs

Reads the live output of every running job (condor_tail): setup phase, ITE iteration and step, and how long it is in it. A warning marker on a running point means it used almost no CPU for more than 30 minutes (stuck).

Phase diagram

Actions

1Submit / continue sweep Pulls the latest code on the access point, then submits every grid point without a result on the laptop or the access point. Each job runs the simulation and its observables. Points that are done or already queued are skipped. To continue unconverged points, raise MAXITER first: they resume from their stored state (uploaded from the laptop if needed) up to MAXITER steps in total. FORCE restarts every point from scratch.
2Gather data Copies finished results to the laptop, then deletes them and their logs on the access point. A file is only deleted after it was copied completely.
3Phase-diagram plot Runs the plot script on the laptop's data (κ, density fluctuation δn, |⟨a⟩|², ρ, S_bstd, phases from κ and S_bstd, |⟨a⟩|² only for low κ with high S_bstd), using KAPPA_TOL, SBSTD_TOL and A2_TOL below.
Recompute observables For points whose observables are missing or outdated (changed observables script, or another N_EDGE). Uploads only those states and runs observables-only jobs, several points per job (Points per obs job); the simulation is not rerun. Gather afterwards.
Remove held jobs Read their log first (click a red point), then press Submit to run them again.
Cancel sweep Removes every queued, running or held job of this sweep. Stored results are kept.
